# B1 — MCP request contract vs the deployed machines_conf pin

**Status:** Accepted
**Date:** 2026-09-05
**Task:** bd-21ef.2.5 (C2 / B1, ADR-4 "reject at the outermost layer")
**Blocking:** machines_conf must be notified before this lands.

---

## Why this note exists

B1 closes both request boundaries: the Elixir tool schemas set
`additionalProperties: false` and reject an undeclared argument by name, and every
Rust dispatch method gained a `#[serde(deny_unknown_fields)]` request struct.
Closing a boundary can only break callers that were relying on it being open, so
the field set the *deployed* fleet actually sends has to be enumerated from the
deployment, not from merged code.

## What "deployed" means here

`machines_conf` `flake.lock` pins `agentic-kb` at
`058f82bdb650a1de44de167adea0672c54f1f2c1` (2026-09-03). That revision's
`mcp/lib/agentic_kb_mcp/mcp_server.ex` builds every port request, so its
`dispatch_tool/3` clauses are the authority on what reaches the Rust side.
Those clauses are byte-identical to this branch's, and
`lib/fb-hm/methodology/kb-protocol.md` at machines_conf HEAD is byte-identical to
the file deployed at `~/.local/share/agents-methodology/kb-protocol.md`.

No other client speaks the port protocol: a repository-wide search for port
request literals in `machines_conf` and in this repository finds only the Elixir
dispatcher and the test fakes.

## Fields the deployed pin sends

Every request also carries `method` and `id`, generated by the dispatcher.

| Tool | Port method | Request fields |
|---|---|---|
| `kb_search` | `search` | `query`, `limit`, `mode`, `path_prefix`, `tag`, `inline_verify_k`, `expand_ids` |
| `kb_add` | `add` | `path`, `summary`, `content`, `tags`, `permanent`, `replace_path`, `kind`, `evidence`, `cues` |
| `kb_cite` | `cite` | `path`, `start`, `end` |
| `kb_import` | `import` | `path`, `upsert` |
| `kb_stale_check` | `stale_check` | `files`, `commits`, `blame` |
| `kb_expire` | `expire` | `entry_id`, `reason`, `force` |
| `kb_run` | `run` | `test_id`, `result`, `adapter`, `detail` |
| `kb_test_add` | `test_add` | `app`, `name`, `protocol`, `config`, `test_id` |
| `kb_tests` | `tests` | `app` |
| `kb_reembed` | `reembed` | `dry_run`, `max_chars` |
| `kb_compact` | `compact` | none |
| `kb_rebuild` | `rebuild` | none |
| `kb_get` | `kb_get` | `entry_id` |

`put_if_present/3` omits a `nil` argument, so any subset of a row can arrive.

Two asserted invariants keep this table honest:
`test_deployed_machines_conf_pin_fields_are_all_accepted` in `src/commands/mcp.rs`
deserializes each row into its typed struct and routes it through the live
dispatcher, and `"every field the deployed machines_conf pin sends is accepted"`
in `mcp/test/agentic_kb_mcp_test.exs` runs the same table past the new argument
allow-list.

## Fields accepted beyond the pin

The Rust structs accept a superset, so nothing that used to work stops working:
`search` also takes `peers`, `reachable_from`, `max_hops` and `slug`, and `add`
also takes `session_id`. S1 now exposes `audit_run`, `audit_record`,
`audit_report`, and `provenance` as the Elixir tools `kb_audit_run`,
`kb_audit_record`, `kb_audit_report`, and `kb_provenance`. The `kb_peers_*`
methods remain port-only and have no Elixir tool.

## Behaviour changes the fleet will see

1. **An undeclared tool argument is now an error.** It was previously dropped in
   silence. An agent passing, say, `confidence` to `kb_add` now gets a message
   naming the key instead of a write that quietly ignored it.
2. **`limit` and `inline_verify_k` out of range are now errors, not clamps.**
   The accepted ranges are `1..=db::MAX_LIMIT` and `0..=db::MAX_INLINE_VERIFY_K`,
   referenced by name so C3's constants and this boundary cannot disagree. The
   `kb_search` tool description still says "clamped to 100"; it is updated to say
   the value is rejected.
3. **A wrong-typed `summary` or `content` is an error.** It previously became an
   empty string, storing an entry with no summary.
4. **`expand_ids` with a non-string member, or more than 32 members, is an
   error.** Non-string members were previously filtered out and the array
   truncated, so a caller could believe it had expanded seeds the server dropped.
5. **A request line over 10 MiB yields `line_too_long`** and the reader discards
   to the next newline. The connection is not dropped and the next request is
   answered.
6. **A `query` over 8 KiB is an error** before it reaches the embedder or FTS.
7. **A non-array `evidence`, `files`, `commits` or `cues` is now an error.** Each
   was previously read with `as_array()` and *ignored* when it was not one, so
   `kb_add` with `"evidence": {...}` stored an entry with no evidence and said
   nothing. Non-string members of `files`, `commits` and `cues` were likewise
   filtered out; they are now rejected.
8. **A non-array `expand_ids` is now an error.** It was previously ignored, and
   the request fell through to an ordinary query search — which failed with
   "missing query" if no `query` was supplied, and otherwise silently answered a
   different question than the caller asked.
9. **`limit: 0` is now an error.** The accepted range starts at 1. It previously
   reached `search_entries` and returned an empty result set.
10. **A `tools/call` whose `arguments` is neither an object nor null is now an
    error.** A missing key and an explicit JSON null both still mean "no
    arguments"; a string or an array is refused rather than coerced.
11. **With no database, the "run `kb init`" hint wins over an argument error.**
    Argument validation runs ahead of dispatch, but it is skipped when there is
    no database to call, because the hint is the only thing the caller can act
    on at that point.
12. **`audit_record` rejects `verdict:false` without a non-empty, trimmed
    `note`.** The error names the offending entry, and the whole request is
    rejected before any write.
13. **`audit_record` rejects more than 50 verdicts.** This matches the maximum
    `audit_run` sample size and bounds one request's write amplification.
14. **`audit_record` rejects a false verdict for a permanent entry.** The error
    names the entry and the `permanent` reason; no expire event or audit row is
    written. Explicit `expire` retains its existing `force=true` override.

### Audit tools

`kb_audit_run` freezes up to 50 candidates. `kb_audit_record` accepts at most
50 verdicts from that run; destructive false verdicts require an explanation
and cannot expire permanent entries. `kb_audit_report` summarizes recorded
results, and `kb_provenance` walks the derived-from graph.

Two things the closure did *not* change, checked against the base commit so the
table is not read as broader than it is: an **empty** `expand_ids` array was
already rejected before B1 (`expand_ids must be a non-empty array of entry ids`),
and a non-array `tags` was already rejected by `validate_kb_add_inputs`.

Changes 1, 4 and 7 are the ones an existing agent could plausibly trip. None is
silent: each names what was wrong.
